# Chat reading

The candidate reading adapter protects the visible paragraph, code block, list item or file table after scrolling upward in a qualified conversation. Streaming below it and resizing/collapsing earlier content should preserve that block's viewport offset. **Jump to latest** above the composer releases the anchor and moves to the end. Returning to the bottom through ordinary scrolling also releases it. Codex retains ownership of normal follow-at-bottom behavior.

The adapter uses public conversation/composer identity and thread-scroll markers. Conflicting identities, inactive pages and unknown layouts retain native behavior. It does not move native message nodes, change message text, alter drafts or access private framework state. Anchors are live element references in memory, discarded on chat changes/disposal. If an anchored block disappears, another captured visible block is used; removed text cannot itself be preserved.

`features/chat/reading-anchor.ts` owns the reading state and geometry. `host/native-surfaces/chat-reading.ts` qualifies the current native viewport and owns the small Jump control. Activity following uses this same owner through `followLatest()`; it cannot override a reading pause or an active scroll gesture.

## Activity while working

In the qualified candidate layout, available native tool disclosures open once as they appear during the current turn. This exposes the progress and command output Codex already provides. It does not recover hidden reasoning, fetch extra logs, or reconstruct native output. The native handlers still own expansion and the user can collapse a section again.

New activity follows the conversation bottom only if the shared reading controller was already following. Scrolling up pauses it; **Jump to latest** resumes. Installing the adapter while already reading history does not jump to the end. Nested terminal/output scrollers retain their native behavior.

Completion/cancellation remains native: the adapter never closes sections itself, never toggles an already open disclosure, and never reopens an item it already visited. Once Stop disappears, the turn is retired. Manually reopening old activity still works. Native grouping changes retain the visited item IDs so a combined group does not reopen after manual collapse. Returning to a cached chat preserves these choices for the 16 most recently active chats; older state and all state on renderer restart are discarded.

`host/native-surfaces/chat-activity.ts` qualifies the last `data-content-search-turn-key`, its `group/agent-activity`, direct `group/activity-header` disclosure, local item IDs and local ARIA label relationship. A completed turn's final-message controls disqualify it. Only the observed English composer **Stop** control is currently recognized; a localized or changed layout stays native. Disabled/hidden/malformed controls, mismatched chats and hidden documents are not acted on. IDs only are retained in memory, capped at 512 items per turn and 128 retired turns per retained chat. No commands, output or typing content is stored.

Run `node scripts/test-chat-activity.mjs` alongside the reading suite. Its synthetic native handlers cover streaming, manual collapse, grouping, completion/cancellation, later turns, cached chats, inactive/ambiguous identity, paused reading, explicit resume and disposal. Public DOM structure was inspected read-only in the native app; **live candidate interaction is still pending**. Other activity presentations and future host versions are not certified. This does not make native completion timing or nested output scrolling part of our implementation.

Local verification: `node scripts/test-chat-reading.mjs` uses actual browser wheel/keyboard input and tests streaming, reflow, native scroll displacement, collapse, fractional zoom, lifecycle and draft preservation. Live character ranges preserve a line within a rewrapped paragraph without touching selection. A concurrent native follow jump during upward wheel input is covered too. These synthetic checks are not proof of native-version compatibility. A temporary live mount succeeded on 26.1023.6621.0 and was removed cleanly; foreground input was unavailable, so live interaction remains pending.
